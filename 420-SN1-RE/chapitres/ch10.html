Problème d'ouverture

Ta simulation de la trajectoire d'une sonde donne une altitude de −3000 m au lieu de 3000 m. Aucun message d'erreur : Python a fait exactement ce que le code lui demandait. Comment trouver l'erreur dans 60 lignes de code, sans tout réécrire au hasard?

Ce chapitre présente une méthode de débogage, puis NumPy, la bibliothèque de calcul scientifique de Python. NumPy fait en une ligne ce qu'une boucle fait en cinq, ce qui laisse aussi moins de place aux erreurs.

Trois familles d'erreurs

Famille Quand on la voit Exemple Message
Syntaxe avant l'exécution if x > 0 sans deux-points SyntaxError
Exécution pendant l'exécution liste[10] dans une liste de 5 éléments IndexError, TypeError, NameError…
Logique jamais : le programme se termine (a + b) / 2 écrit a + b / 2 aucun

Les erreurs de logique sont les plus difficiles, parce que rien ne les signale. Seul ton jeu d'essais les révèle.

Lire un message d'erreur

Quand l'erreur se produit dans une fonction appelée par une autre, le message, appelé traceback, montre toute la chaîne des appels. Lis-le de bas en haut : la dernière ligne donne l'erreur, et la ligne juste au-dessus dit où elle s'est produite.

Le message pointe la ligne de moyenne, mais la vraie cause est l'appel avec une liste vide, deux niveaux plus haut. Le traceback donne le chemin; c'est à toi de remonter jusqu'à la cause.

Une méthode en cinq étapes

  1. Reproduire. Trouve un cas précis qui donne un mauvais résultat, et note le résultat attendu.
  2. Lire. S'il y a un message, lis la dernière ligne, puis la ligne de ton code qui est en cause.
  3. Localiser. Ajoute des print() aux endroits clés, ou fais la trace à la main, pour trouver la première ligne où une valeur devient fausse.
  4. Corriger une seule chose. Formule une hypothèse (« l'accumulateur repart de zéro à chaque tour »), corrige, puis réexécute.
  5. Retester tout le jeu d'essais, pour t'assurer que la correction n'a rien brisé ailleurs.

Un truc pratique : afficher le nom et la valeur

Dans une f-string, {x=} affiche le nom de la variable et sa valeur : print(f"{i=} {total=}") affiche i=3 total=14. C'est idéal pour suivre une boucle.

Les print() montrent tout de suite que total repart de 0 à chaque tour : l'initialisation est dans la boucle. Déplace-la avant la boucle, puis enlève les print() de débogage.

La méthode du canard

Explique ton code, ligne par ligne et à voix haute, à quelqu'un, ou même à un canard en caoutchouc. Très souvent, on trouve l'erreur en plein milieu de son explication.

Les erreurs classiques à soupçonner

  • Un tour de trop ou de moins : range(n) contre range(n + 1), < contre <=.
  • Une initialisation placée dans la boucle.
  • Un return placé dans la boucle : la fonction s'arrête au premier tour.
  • Les priorités des opérations : a + b / 2.
  • Un elif dans le mauvais ordre.
  • Un nombre lu au clavier ou dans un fichier qui est resté du texte.

NumPy : calculer sur des tableaux entiers

NumPy fournit un nouveau type de tableau, ndarray, fait pour le calcul. Une opération sur un tableau s'applique à tous ses éléments à la fois, sans boucle.

Piège : une liste n'est pas un tableau NumPy

Avec des listes, [1, 2] + [3, 4] donne [1, 2, 3, 4] (on les met bout à bout) et [1, 2] * 2 donne [1, 2, 1, 2]. Avec des tableaux NumPy, + et * agissent élément par élément. Convertis tes listes avec np.array() avant de calculer.

Créer des tableaux

Fonction Résultat
np.array([1, 2, 3]) à partir d'une liste
np.linspace(0, 2, 5) 5 valeurs régulièrement espacées de 0 à 2, fin incluse : 0, 0.5, 1, 1.5, 2
np.arange(0, 1, 0.25) de 0 à 1 par pas de 0.25, fin exclue : 0, 0.25, 0.5, 0.75
np.zeros(4) quatre zéros

Le programme à corriger

On veut l'énergie mécanique d'une balle lancée vers le haut à 15 m/s, toutes les 0.5 s, de 0 à 3 s. L'énergie devrait rester constante, à 112.5 J, pour une masse de 1 kg. Le programme ci-dessous contient deux erreurs : applique la méthode pour les trouver.

Étape 1, reproduire : à t = 0, l'énergie devrait être ½ × 1 × 15² = 112.5 J, mais le programme affiche 122.3 J. Étapes 2 et 3 : à t = 0, y vaut 0; l'erreur est donc dans la formule de l'énergie potentielle, écrite m * g + y au lieu de m * g * y. Après correction, une deuxième erreur reste : la table s'arrête à 2.5 s. range(6) donne 6 instants; il en faut 7 pour aller jusqu'à 3 s.

La version NumPy

Plus court, sans indice ni range() à gérer : deux sources d'erreur de moins. L'énergie reste à 112.5 J à chaque instant, comme prévu.

Pièges fréquents

  • Corriger plusieurs choses à la fois : on ne sait plus laquelle a réglé le problème.
  • Oublier d'enlever les print() de débogage.
  • Mélanger listes et tableaux NumPy dans un calcul.
  • Oublier ddof=1 pour l'écart type d'échantillon.
  • Confondre np.linspace (fin incluse, nombre de points) et np.arange (fin exclue, pas).
