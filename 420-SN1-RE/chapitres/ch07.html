Problème d'ouverture

Depuis le chapitre 6, tu écris des fonctions utiles : conversions, énergies, classifications. Deux questions se posent. Comment les réutiliser dans un autre programme sans les recopier? Et comment être sûr qu'elles sont justes, même après les avoir modifiées?

La réponse tient en deux outils : les modules, qui rangent des fonctions pour les réutiliser, et les tests automatisés, qui vérifient un jeu d'essais en une seule exécution.

Importer un module

Un module est un fichier qui regroupe des fonctions et des constantes. Python en fournit des centaines. Il y a trois façons de les importer :

Écriture Utilisation Quand l'utiliser
import math math.sqrt(2) Par défaut : on voit d'où vient chaque fonction
import statistics as st st.mean(...) Nom de module long
from math import sqrt, pi sqrt(2), pi Quelques fonctions très utilisées

[9.79, 9.83, ...] est une liste de valeurs. On l'utilise ici seulement pour donner des mesures au module statistics; les listes sont le sujet du chapitre 8.

Piège : un nom écrasé

Après from math import pi, une ligne pi = 3 remplace la valeur de π dans tout le programme. Avec import math, la valeur reste protégée dans math.pi. Dans le doute, préfère import math.

Les modules utiles en sciences

Module Exemples
math sqrt, exp, log, log10, sin, cos, radians, pi, e
random random, randint, uniform, seed
statistics mean (moyenne), median (médiane), stdev (écart type)

On trouve la liste complète des fonctions d'un module dans la documentation officielle de Python, ou avec help(math).

Un module maison

Un module maison, c'est simplement un fichier .py qui contient tes fonctions. Si le fichier physique.py contient def energie_cinetique(m, v): ..., n'importe quel programme du même dossier peut écrire import physique puis physique.energie_cinetique(2, 3).

L'exemple ci-dessous crée le fichier du module avec du code, puis l'importe. Sur ton ordinateur, tu créerais plutôt le fichier physique.py dans ton éditeur.

Avantages : une seule copie de chaque fonction, qu'on corrige à un seul endroit; des programmes principaux plus courts et plus lisibles.

Les tests automatisés avec assert

Depuis le chapitre 1, tu construis un jeu d'essais, puis tu compares les résultats à la main. L'instruction assert fait cette comparaison pour toi :

assert condition, "message si la condition est fausse"

Si la condition est vraie, rien ne se passe. Si elle est fausse, le programme s'arrête avec une AssertionError et ton message.

Essaie-le

Introduis une erreur dans la fonction, par exemple c + 273. Quel test échoue en premier? Le message te dit lequel.

Regrouper les tests dans une fonction

On regroupe souvent les tests d'une fonction dans une fonction de test, qu'on exécute après chaque modification. C'est ton jeu d'essais, rendu automatique.

Exemple complet : écrire les tests d'abord

On peut écrire les tests avant la fonction : c'est le jeu d'essais de la fiche de planification, traduit en assert. On écrit ensuite la fonction jusqu'à ce que tous les tests passent.

Planifier

Fonction annee_bissextile(annee) : divisible par 4, sauf les années divisibles par 100, à moins qu'elles soient divisibles par 400.

Année Attendu Pourquoi
2024 True divisible par 4
2023 False pas divisible par 4
1900 False divisible par 100
2000 True divisible par 400

Coder : les tests, puis la fonction

Vérifier

Les tests passent. Remplace la fonction par une version naïve, return annee % 4 == 0, et exécute : le test de 1900 la démasque immédiatement. C'est tout l'intérêt d'un jeu d'essais qui contient les cas particuliers.

Pièges fréquents

  • Écrire assert entre parenthèses avec un message : assert (x == 1, "message") est toujours vrai. Écris assert x == 1, "message".
  • Comparer des réels avec == dans un test.
  • Ne tester que le cas « normal », jamais les bornes.
  • Donner à une variable le nom d'une fonction importée.

Exercice 7.2 — Quel test échoue?

À faire

Sans exécuter de code : lequel de ces quatre tests provoque une AssertionError? Donne son numéro.

def double(x):
    return x * 2

assert double(0) == 0          # test 1
assert double(-3) == -6        # test 2
assert double(0.1) == 0.2      # test 3
assert double(0.1 + 0.2) == 0.6   # test 4
